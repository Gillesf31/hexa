Problem resolved
The former app-only structure asked maintainers to remember dependency direction.
Current shape
Nx tags and @nx/enforce-module-boundaries restrict the allowed imports. provideAppointmentsFeature() concentrates adapter selection and use-case construction at the composition seam.
Why keep it
Locality: a forbidden import fails at the source. Leverage: callers only need the small interfaces of their own modules. The deletion test succeeds: removing this structure would spread wiring and dependency knowledge back across callers.

Problem
The HTTP adapter hard-codes the endpoint and the primary adapter creates its signal from the use-case result, but neither interface is exercised in a test. The feature target accepts an empty test suite.
Solution
Add one HTTP adapter contract test that fixes request method, URL, and response mapping; add one primary-adapter test with a controlled AppointmentsPort adapter that proves the rendered fields and empty state.
Benefits
Locality: integration and rendering regressions fail at their seams, without a running server. Leverage: each test crosses the same interface as its callers, rather than testing internal details.

  MEM --> PORT
  classDef deep fill:#0f172a,stroke:#0f172a,color:#fff;

Problem
The public provider interface uses a boolean to select production or sample data. The checked-in guidance instead calls for a separate, explicit dev/test composition that cannot accidentally be selected by production startup.
Solution
Keep the production composition deep and simple; introduce a deliberately local dev/test composition that overrides the port adapter. Design this with the existing Nx tags before changing it.
Benefits
Locality: the active data source is visible at a single startup seam. Leverage: the feature and application modules remain unaware of the selected adapter. This is a real seam because HTTP and in-memory adapters already exist.

Problem
Filtering depends on the implicit invariant that every date is a zero-padded YYYY-MM-DD string. The system clock creates that form, but the HTTP adapter accepts it unchecked.
Solution
Do nothing yet for this increment. If invalid input, time zones, or date arithmetic enter the requirements, introduce one calendar-date module that owns parsing, canonical form, and comparison before appointments enter the domain rule.
Why speculative
Today there is no product requirement for date validation or time-zone conversion. Adding a seam before that variation exists would reduce depth; with only the current known format, the simple implementation has better locality.

Top recommendation

Test the two edges that callers rely on

It protects the user-visible path without widening the architecture: the existing port interface and two real adapters already supply the seam. The test suite is currently strongest where risk is lowest, so this gives the most immediate leverage.
